# Workstate

> 把散落在 Codex 会话里的工作进展，整理成一张可以继续推进的项目地图。

Workstate 是一个运行在 macOS 菜单栏里的本地应用。

当同一个项目持续数周、分散在多个 Codex 会话中时，聊天记录虽然还在，但项目状态很容易丢失：已经确认了什么、同时在做哪些任务、某次修改为什么发生，以及下一次应该从哪里继续，都需要重新翻阅和解释。

Workstate 会读取已经完成的 Codex 对话，找出真正改变项目状态的内容，再按项目和工作线重新组织。它不保存“每句话的摘要”，而是维护一份持续更新、可以追溯来源的项目状态。

![项目图谱](docs/images/project-graph.png)

## 它记录什么

对每个项目，Workstate 主要维护六类信息：

- **项目背景**：这个产品是什么，目前已经发展到什么状态
- **当前工作**：现在真正处于焦点的主线，以及确实同时推进的并行工作
- **关键变化**：实现、决定、验证、问题和交付分别发生了什么
- **待决策议题**：未来可能推进，但还没有决定是否要做
- **待验证议题**：本轮工作已经结束，但仍在等待结果、反馈或验收
- **原始证据**：每个结论来自哪一段 Codex 对话或本地文档

因此，即使切换项目、开启新会话或发生上下文压缩，后续协作仍然可以从现有项目状态继续，而不必只依赖当前聊天窗口的记忆。

## 三层视图

### L1 · 现在有哪些项目

第一层是一张可以拖动的项目图谱。

每个节点代表一个项目。节点的颜色和状态表示它正在进行、等待、完成，还是已经很久没有更新；项目之间的连线表示工作转移、共享能力或其他实际关系。

这里解决的是全局问题：**我现在同时在推进什么，注意力分布在哪里？**

每天上午 9 点，Workstate 还会整理上一个有实际对话发生的工作日。没有工作变化时不会生成空摘要，上一份有效摘要会继续保留。

L1 右下角还有两个全局入口：

- **全局 Project Owner**：不用先选择项目。消息会先被路由到最相关的项目，再由对应 Owner 接手讨论。
- **协作档案**：查看 Workstate 持续沉淀的用户习惯、协作者 Persona、规则、禁忌和工作 Loop，也可以直接与维护档案的 Agent 讨论和修订。

### L2 · 一个项目进行到哪里

进入项目后，上方是持续更新的项目背景，下方是按时间排列的工作历史，最新进展始终显示在最上面。

时间线中间是一条项目主线。项目始终显式记录当前焦点工作线；只有证据表明两个任务确实同时推进时，才会从前一个节点分出支线并在后续节点合回。顺序发生的任务继续留在主线上，不会因为日期范围重叠就制造分支。

工作历史支持两种查看方式：

- **时间**：按真实发生顺序查看项目怎样推进、切换和并行
- **分支**：按工作线查看同一方法或任务内部的完整变化，并可选择是否显示已经结束的分支

最新节点常驻显示标题和时间；历史节点保持安静，需要时再查看详情，避免文字互相覆盖。

![项目时间线](docs/images/project-timeline.png)

项目页还包含三个独立入口：

- **议题**：区分待决策与待验证；可以确认推进、确认完成、继续跟进或取消
- **Project Owner**：与只负责这个项目的 Agent 对话，讨论产品方向、整理议题或校正项目理解
- **上下文交接**：点击 L2 顶部的复制按钮，生成最新项目交接文件并复制接手 Prompt，让其他 IDE 直接读取

这一层解决的是项目问题：**事情是怎样发展到现在的，目前有哪些任务仍未结束？**

### L3 · 这次变化为什么发生

点击时间线节点，会打开原生 macOS Popover。

里面记录这次变化的结果、已经确认的决定、涉及范围、当前交付状态，以及对应的原始对话和文档。它让时间线上的一句结论可以继续追溯，而不是变成无法验证的 AI 摘要。

![变化详情](docs/images/delta-detail.png)

这一层解决的是细节问题：**这个结论具体是什么意思，依据又在哪里？**

## 一条对话如何变成项目状态

一轮 Codex 对话结束后，后台会依次完成这些工作：

1. **发现变化**：Session Watcher 只读取发生增量的会话文件，不反复加载和分析全部历史。
2. **等待收口**：新片段先进入安静期。同一轮连续对话会合并处理，避免每句话触发一次模型调用。
3. **找到项目**：Portfolio Router 只判断内容属于哪个项目，不负责理解任务细节。
4. **理解工作**：对应项目的 Project Steward 结合现有背景，逐段判断继续主线、建立独立工作线、真实并行或结束工作线。
5. **承接遗留**：工作线结束后不长期“停放”。仍未决定是否继续的内容进入待决策议题；等待结果或验收的内容进入待验证议题。
6. **校验并写入**：本地写入层检查项目、工作线、焦点和父节点是否真实存在，确认状态一致后再保存。

Router 可以创建新项目，Project Steward 可以创建新工作线。一个安静期批次可以保留多次真实任务切换，不会把整段对话压成一个大事件。只有分析结果与现有状态矛盾时，当前更新才会暂停并记录可诊断错误，避免把内容写进错误的位置；其他项目和后台监听不会因此停止。

后台不是按秒全量扫描。文件监听、安静期、持久化处理阶段和批量 Agent 调用共同限制重复工作。进程重启后会从已经落盘的阶段继续，不会重跑已完成步骤。

## 议题与工作线

工作线表示正在发生的执行，不是无限期保存的待办容器。

- 工作完成且结果明确：工作线结束
- 本轮结束，但未来是否继续尚未决定：工作线结束，生成**待决策**议题
- 本轮结束，但结果、反馈或验收仍未知：工作线结束，生成**待验证**议题
- 两项工作有证据表明确实同时推进：保留为并行工作线

待决策议题可以确认推进或取消；待验证议题可以确认完成、继续跟进或取消。继续推进时会生成新的正式工作线，并保留与原议题的关系。

Project Owner 对话只会把新想法保存为议题，不会擅自把聊天内容写成已确认事实。正式进入项目流程仍需要用户在议题界面确认。

## 跨 IDE 接力

Workstate 可以为项目、工作线或已知 Codex 会话生成紧凑的上下文交接包：

```bash
workstate handoff project <project-id>
workstate handoff task <task-id>
workstate handoff thread <thread-id>
```

交接包包含当前项目背景、焦点工作、未决议题、已确认决定、禁止方向、协作方式和原始来源定位。L2 的复制按钮会把最新版本写到：

```text
~/.codex/workstate/handoffs/<project-id>.md
```

随后复制一段包含绝对路径的接手 Prompt。任何能读取本地文件的 Coder 或 IDE 都可以据此继续工作。当前版本只会自动监听 Codex 会话；Kimi、Claude 等其他会话来源仍待接入。

## 数据与隐私

项目状态、议题、Owner 对话、协作档案、每日摘要、交接文件和来源定位保存在：

```text
~/.codex/workstate
```

这些运行数据不会写入 Git，也不会被包含在应用构建产物中。

Workstate 使用本机已经登录的 Codex 进行项目归属和内容分析，因此相关对话内容仍会通过 Codex 服务处理。Router、Project Steward、Project Owner、日报和协作档案维护可以分别配置模型与推理强度。仓库中的截图使用独立的匿名演示数据。

## 首次启动

新的工作区不会自动导入全部历史。第一次打开 Workstate 时，需要完成一次冷启动：

1. 选择要读取的时间范围和 Codex 任务。
2. 填写当前已知的项目边界，也可以给某些任务提供项目归属提示。
3. 为 Router、Project Steward、Project Owner、历史整理、项目重建、日报和协作档案分别选择模型与推理强度。
4. 在确认页检查完整回合数和实际会送入 Agent 的证据量，再开始建立工作区。

时间范围之外以及没有被选中的历史不会进入 Workstate。冷启动会按阶段保存已经完成的路由、历史整理和项目重建结果；中途停止后可以继续，不会重跑已经落盘的 Agent 工作。

右上角的设置入口可以随时修改各 Agent 的模型，或关闭实时监听。关闭监听期间的新对话只会被跳过，不会在重新开启后形成待处理积压。

## 构建与运行

要求：

- macOS 14 或更高版本
- Swift 6.2
- Node.js 18 或更高版本
- 已完成登录的 Codex

```bash
git clone https://github.com/zyshutim/workstate.git
cd workstate

npm install --prefix AgentRuntime
npm run build --prefix AgentRuntime
swift run WorkstateChecks

./scripts/build-app.sh
./scripts/install-cli.sh
./scripts/install-daemon.sh --start
open dist/Workstate.app
```

应用会生成在 `dist/Workstate.app`。后台服务安装在 `~/Library/Application Support/Workstate`，并通过本地 LaunchAgent 监听新的 Codex 对话。

## 当前状态

Workstate 目前是一个正在真实工作流中使用的 MVP，尚未提供经过 Apple 公证的发行包。

当前版本已经包含：

- 可拖动、缩放和查看项目关系的 L1 项目图谱
- 显式主线、真实并行分支、时间/分支切换和历史过滤
- 原生 Popover 承载的 L3 变化详情与原始证据
- 待决策/待验证议题，以及确认推进、确认完成、继续跟进和取消
- 项目 Owner、全局 Owner 与可持续修订的协作档案
- 每日上午 9 点生成的上一有效工作日摘要
- 冷启动历史导入、分阶段恢复、模型设置和实时监听开关
- 项目/工作线/会话级上下文交接 CLI、Skill 和 L2 复制入口
- 文件增量监听、安静期批处理、持久化处理状态与运行资源保护

仍未完成的主要部分是其他 Coder 会话来源接入、面向普通用户的签名安装包，以及更完整的数据校正和错误恢复界面。
