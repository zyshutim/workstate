# Workstate

> 让我不用重新回忆，让 Agent 不用我重新解释，也让我们不用每次重新磨合。

Workstate 是一个运行在 macOS 菜单栏里的本地应用。

它把散落在不同 AI 会话里的项目进展，整理成一份人和 Agent 都能使用的长期记忆。

当多个项目同时推进，或者工作不断在不同会话、模型和客户端之间切换时，真正容易丢失的不是聊天记录，而是项目现在到了哪里、为什么变成这样、已经决定了什么，以及接下来应该做什么。

Workstate 希望把这些内容持续保存下来。

![项目图谱](docs/images/project-graph.png)

## 聊天是一条线，工作不是

聊天只能按照时间顺序不断向下延伸，但人的思维不会始终沿着一条线前进。

人会临时切换问题、回头确认以前的决定，也会在一段普通讨论里随口说出后来非常重要的认知。并行不只发生在项目之间，也会发生在项目内部。

做同一个项目时，人可能刚刚还在调整一个模块，下一刻又切到另一个模块；中间有人来确认设计事实，还需要暂时离开当前工作，去查找已经确定的文档、决定和原始记录。这些工作线会不断分开、切换、暂停、回来和合并。

时间久了，人很难从一条漫长的聊天流里找回某句话。Agent 经过上下文压缩后也可能失去这段认知，而模型自己的 Memory 还可能不完整、已经过期，或者记错了重点。

所以 Workstate 不只是保存更多聊天记录。它会把线性的对话流重新拆成项目、工作线、决定、议题、认知和证据，并记录每条线从哪里开始、现在做到哪里、为什么暂停，以及之后应该回到哪里。

以后再问“我们当时是怎么定的”，系统应该找到对应的认知和原始对话，而不是让 Agent 凭印象回答。

- 对话记录是证据
- Workstate 是长期共享记忆
- 模型上下文是临时工作区
- 模型自己的 Memory 不能代替事实来源

## 我不用重新回忆

Workstate 会把项目里的重要内容重新组织起来：

- 项目现在是什么状态
- 当前主线、并行支线和刚刚切走的位置
- 过去发生过哪些关键变化
- 已经确认了哪些决定
- 哪些方向已经被否定
- 还有哪些议题、灵感和待办
- 每个结论来自哪段原始对话

这些内容不会只藏在聊天记录里，而是通过项目图谱、工作时间线、节点详情和每日总结重新呈现。

每天开始工作时，Workstate 会告诉我：

- 上一个工作日推进了什么
- 确认了什么
- 哪些项目仍在进行
- 今天应该从哪里继续
- 接下来最重要的目标是什么

我不需要重新翻阅所有会话，才能想起昨天做到了哪里。

## Agent 不用我重新解释

Workstate 保存的不是只给人看的笔记。

它也会为 Agent 准备可以直接接手工作的上下文，包括：

- 完整的项目背景
- 当前项目认知
- 当前主线、并行支线和每条线的进度
- 已确认的决定和禁止方向
- 尚未解决的议题
- 相关的原始证据
- 用户当前的态度和协作方式

不管换成哪个模型、哪个客户端或哪个 IDE，新 Agent 都应该能够读取这份上下文，马上继续工作，而不是要求用户重新解释一遍项目。

Workstate 目前可以生成项目、工作线或 Codex 会话的交接文件：

```bash
workstate handoff project <project-id>
workstate handoff task <task-id>
workstate handoff thread <thread-id>
```

交接文件保存在：

```text
~/.codex/workstate/handoffs
```

## 我们不用每次重新磨合

项目记忆之外，Workstate 还会保存人和 Agent 是怎样协作的。

它会持续整理：

- 用户怎样思考和做决定
- Agent 应该怎样说话和做事
- 已经形成的 Rules、Skills 和 Loops
- 哪些工作方式已经被否定
- 从长期协作中发现的新习惯

这些内容组成一份可以继续修订的协作档案。

换一个 Agent 时，继承的不只是项目背景，还有双方已经建立起来的工作方式。

## 一套持续运转的循环

Workstate 里的项目认知、议题、Project Owner 和上下文交接不是彼此分开的功能。

它们共同组成一套循环：

```text
工作会话
→ 更新项目认知和进展
→ 沉淀议题、灵感和待办
→ 与 Project Owner 继续讨论
→ 确认后进入正式工作
→ 生成上下文交接
→ 其他 Agent 接手
→ 新进展重新回到 Workstate
```

Workstate 的目的，是让这条循环可以跨越会话、模型和客户端继续运行。

## 界面

### L1 · 项目图谱

查看所有项目、当前状态，以及项目之间的关系。

它回答的是：**我现在同时在推进什么？**

### L2 · 项目进展

进入一个项目后，可以看到：

- 当前项目认知
- 正在推进的任务
- 任务切换、并行分支、临时打断和历史进展
- 议题、灵感和待办
- Project Owner 对话

它回答的是：**这个项目现在到了哪里？**

![项目时间线](docs/images/project-timeline.png)

### L3 · 变化详情

点击时间线节点，可以查看这次变化具体做了什么、确认了什么，以及它来自哪段原始对话。

它回答的是：**这件事为什么会变成现在这样？**

![变化详情](docs/images/delta-detail.png)

## 数据与隐私

Workstate 的运行数据保存在本机：

```text
~/.codex/workstate
```

这些数据不会写入 Git，也不会包含在应用构建产物中。

当前版本使用本机已经登录的 Codex 处理项目内容，因此相关对话仍会经过 Codex 服务。仓库中的截图使用独立的演示数据。

## 当前状态

Workstate 目前是一个正在开发和真实使用中的 macOS MVP，还不是正式发行的软件。

当前已经包含：

- 项目图谱和 Git 式工作时间线
- 项目认知、变化详情和原始证据
- 每日工作总结
- 议题、灵感和待办整理
- Project Owner 与全局对话
- 协作习惯档案
- 项目上下文交接

目前主要读取 Codex 会话。其他 Coder 可以通过交接文件接手项目，但自动读取其他客户端会话的能力还没有完成。

后台自动整理仍在继续校正和验证，当前仓库更适合开发与体验，不建议作为无人值守服务长期运行。

## 本地构建

要求：

- macOS 14 或更高版本
- Swift 6.2
- Node.js 18 或更高版本
- 已经登录 Codex

```bash
git clone https://github.com/zyshutim/workstate.git
cd workstate

npm install --prefix AgentRuntime
npm run build --prefix AgentRuntime
swift run WorkstateChecks

./scripts/build-app.sh
./scripts/install-cli.sh
open dist/Workstate.app
```

应用会生成在：

```text
dist/Workstate.app
```
