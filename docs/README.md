# Workstate 文档

这里是 Workstate 后续产品、设计和开发共同使用的项目事实入口。

## 阅读顺序

1. [PRD](PRD.md)：产品解决什么问题，信息如何分层，用户最终看到什么。
2. [技术方案](TECHNICAL_DESIGN.md)：后端如何采集、理解、写入、交接和保护运行安全。
3. [实现状态](IMPLEMENTATION_STATUS.md)：当前代码已经具备什么，哪些仍是旧逻辑，下一步需要迁移什么。

根目录的 [README](../README.md) 面向第一次了解项目的人，只负责介绍产品，不作为产品规则或技术现状的依据。

## 更新规则

- 产品语义、信息结构或交互规则改变时，先更新 PRD。
- Agent 分工、数据契约、处理流程或运行边界改变时，同步更新技术方案。
- 代码完成并经过真实验证后，更新实现状态；仅写完代码不能标记为完成。
- 具体开发任务可以在 `docs/plans/` 下建立临时计划。完成后把最终结论合并回上述正式文档，避免计划文件成为另一套长期事实。
- 文档中必须明确区分“已确认目标”“当前实现”和“待确认问题”，不能把推测写成现行规则。
- 文档与实际运行冲突时，先记录冲突并核对代码和真实数据，再修正文档或实现。

## 当前边界

PRD 已包含 App 的信息架构。详细视觉和交互规范会在正式进入 App 重构时单独建立并从这里链接；当前不提前复制一份尚未稳定的设计文档。
